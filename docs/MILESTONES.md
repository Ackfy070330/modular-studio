# 开发里程碑与验收

以下按依赖和结果排序，不绑定尚未确定的人力与工期。M0 是技术验证；M1–M4 合起来构成第一版的完整闭环。

## M0：打通最难的技术链路

建立一个最小 React/Vite + Fastify + PostgreSQL 示例应用，包含提交订单、计算金额、写入数据库和显示回执。

交付：

- 浏览器请求与后端请求通过真实 Trace 上下文关联。
- 一个业务模块采集输入/输出，并带有环境、运行和代码快照标识。
- 独立调试客户端能命中本地 Node.js 的 TypeScript 断点，读取变量与调用栈。
- 选择一个有可用接入方式的编程智能体，完成一次受范围限制的修改并返回测试结果。

通过条件：四项来自实际运行，并记录复现步骤。若某项失败，先解决或调整兼容范围，再开始完整 UI 开发。

## M1：模块蓝图与持久化

交付项目管理、模块库、画布、契约面板、受限逻辑积木和蓝图版本保存。首批模块覆盖订单场景需要的页面、事件、接口、校验、计算、存储及结果展示。

通过条件：

- 用户能从空画布搭出订单场景并重新打开。
- 端口不兼容、缺少字段、悬空连接、未支持控制流给出可定位诊断。
- 修改模块名称/位置不会改变模块 ID；并发保存冲突不会覆盖新版本。
- 页面配置、契约和业务逻辑独立于画布布局。

## M2：蓝图到真实软件

交付模板生成器、源码绑定清单、智能体任务、工作副本、变更比较、测试与应用流程。

通过条件：

- 从 M1 蓝图得到可运行的前端、接口和数据库操作。
- 至少一个真实智能体能完成自定义业务规则，并执行约定测试。
- 用户能查看模块对应的文件变化；已有未提交内容在工作副本中得到保留。
- 基线已变化时进入冲突处理，不直接覆盖。
- 任务失败、断线和取消有明确状态；测试失败不会显示“已验证”。

## M3：导入项目与真实数据流

交付受支持项目的源码分析、实现结构图、采集配置、执行记录、环境筛选和节点数据面板。

通过条件：

- 能导入一份独立维护的示例项目，识别受支持的请求与路由、函数及数据库操作。
- 导入只读；安装依赖和启动程序是独立操作。
- 一次实际提交展示前端 → 后端 → 业务处理 → 数据库访问 → 结果的观察链路。
- 点击业务模块看到采集到的输入/输出、耗时、环境和对应版本的源码。
- 未接入模块、未知静态关系、丢失上下文、截断与脱敏都有明确标记。
- 重连后补齐可恢复事件，重复上报不产生重复记录。

## M4：调试并由智能体修复

交付本地 Node.js 断点、单步、变量、调用栈，以及选中模块后发起诊断与修复的流程。

验收使用人为植入的“计算金额时忽略数量”错误：输入单价 100、数量 2，错误输出 100。这个错误可能没有异常，因此还需要测试断言和数据对比。

通过条件：

- 从错误执行记录定位计算模块和其源码版本。
- 实际断点命中并能读取 quantity，继续和单步确实控制目标进程。
- 继续执行后，旧栈帧和变量引用不会继续作为当前值显示。
- 传给智能体的任务包含选定代码、脱敏输入/输出和验收条件。
- 修复后新增回归测试，实际输出为 200；两次记录保持各自版本可追溯。
- 历史轨迹回放不重新写数据库或调用外部服务。

M4 完成后才能把首版描述为“同时具备模块化协作开发与可视化调试”。

## M5：扩展与团队化

按实际需求依次增加浏览器实时断点、更多智能体适配器、Express/Next.js/Python 等分析插件、远程环境采集、异步消息关联和团队权限。

每新增一种语言/框架，分别验收“结构识别、采集、源码映射、实时调试”四项能力。支持其中一项不代表其余三项已支持。

## 必要的验证矩阵

| 类别 | 样本与异常条件 | 期望结果 |
| --- | --- | --- |
| 蓝图语义 | 分支、缺失字段、不兼容端口、未支持环路 | 阻止无法执行的蓝图并定位到模块 |
| 源码映射 | 改行号、重命名、构建版本变化、未提交修改 | 正确映射或明确失效，不跳到错误版本 |
| 导入 | 动态 URL、未知驱动、复杂框架写法 | 保留证据与未知项，不补造关系 |
| 运行采集 | 并发请求、异常、嵌套异步、断网、重复与乱序上报 | 不串请求、不丢失已有记录、显示不完整状态 |
| 环境 | 相同业务在本地和测试环境运行 | 可过滤比较，不合并成一次执行 |
| 调试 | 未验证断点、进程退出、连接中断、大变量 | 会话状态真实、引用不过期复用、UI 可响应 |
| 变更 | 基线冲突、测试失败、任务取消 | 不覆盖新内容、不误报完成 |
| 采集边界 | 密钥、Cookie、循环对象、超大快照 | 按策略屏蔽或截断，业务返回结果不受影响 |
| 工作区边界 | 路径穿越、符号链接越界、未授权连接器 | 文件访问和执行被限制在已授权范围 |

## 开工时的默认决策

默认采用 Windows 本地开发优先、单人使用、React/Vite + Fastify + PostgreSQL 的目标项目范围。第一版的后端技术栈也采用 TypeScript/Fastify。

开始真实智能体适配时再确定一个用户可用的供应商或本地智能体；开始远程环境接入时再确定部署方式与采集策略。其余模块可以按本文先行开发，不需要把所有扩展项一次性确定。
